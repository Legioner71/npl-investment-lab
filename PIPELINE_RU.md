# NPL Investment Lab 0.9: единый проект портфеля

Версия 0.9 объединяет вкладки общими данными и прогнозом. Локальный запуск сохранён: распакуйте весь комплект, установите Python 3.10 или новее и откройте START_WINDOWS.bat. Для обычного интерфейса Node.js и установка ML-библиотек не нужны. Для Python CLI проекта нужен Node.js.

## Что изменилось

Верхняя панель на каждой вкладке показывает один и тот же портфель: название, дату оценки, число договоров, источник прогноза и идентификатор версии. Ниже находятся шесть кнопок маршрута. Это навигация по работающим разделам, а не отдельная копия расчётов.

В начале открывается синтетический проект с историей и операционными статусами. Поэтому выбран ML-прогноз на 12 месяцев. Используется базовая Logistic + Ridge из текущего комплекта; точность на реальных украинских портфелях не подтверждена. CatBoost и TabPFN остаются в диагностике сохранённого эксперимента. Браузер не пересчитывает эти два алгоритма для нового реестра.

## 1. Открыть данные

Нажмите «Відкрити дані / проєкт». Поддерживаются:

- CSV реестра по прежней схеме из девяти колонок. Он создаёт новый проект со сценарным прогнозом на 36 месяцев. История и разрешения демонстрационного портфеля к нему не прикрепляются.
- JSON со snapshots и payments. Он создаёт проект на основе этой истории и включает ML на 12 месяцев. Требования к датам и полноте истории прежние: PREPURCHASE_SCHEMA.md.
- JSON с case и operations. case содержит snapshots/payments, operations — accounts. Реестр, история и операционные статусы загружаются вместе.
- Сохранённый JSON проекта с schema = npl-project-v1. Он восстанавливает исходные данные, выбранный источник, бюджет, параметры и применённую стратегию, зафиксированное решение, введённый факт и настройки симуляции. Если карта сравнения была открыта при сохранении, её снимки также включаются.

Лимит JSON — 50 МБ; CSV — до 50 000 договоров. Идентификаторы должны быть уникальными, суммы — неотрицательными. Неизвестные сегменты и дубли вызывают ошибку. Программа сохраняет прежний проект, если проверка нового не прошла. Перед заменой несохранённого проекта появится предупреждение.

У проекта одна дата оценки. В JSON она берётся из as_of_date договоров. Для простого CSV используется текущая дата UTC, поскольку столбца даты в прежней CSV-схеме нет. Для точной исторической даты используйте JSON-пакет или измените as_of_date и согласованные даты в сохранённом файле проекта перед повторным импортом.

## 2. Проверить реестр и прогноз

На вкладке «Реєстр вимог» проверьте количество договоров, номинал и исключения. ready/review относятся к данным договора. У готового по документам договора может отсутствовать ML-прогноз из-за неполной истории; это отдельная причина проверки.

Верхний переключатель источника действует сразу на весь проект:

- «ML · 12 місяців» доступен при наличии истории. Модель оценивает вероятность хотя бы одного платежа и сумму при условии платежа. Их произведение даёт ожидаемые сборы.
- «Сценарний · 36 місяців» использует демонстрационные вероятности и доли возврата по сегментам. Эти значения не обучены на украинской истории.

В «До купівлі · ML» теперь показан выбранный прогноз проекта. При сценарном источнике здесь отображаются сценарные оценки с соответствующей подписью. Таблица и экспорт относятся к текущему реестру. «Діагностика моделей» показывает сохранённую проверку качества кандидатов; её показатели не являются фактом по загруженному портфелю.

Если quality = review, история неполна или операционный статус требует проверки документов, прогноз остаётся неизвестным. Такие договоры не включаются в число неплательщиков. Расходы на обслуживание всего пакета сохраняются. Число ожидаемых плательщиков — сумма вероятностей, а не поимённый список будущих плательщиков.

ML оценивает общие сборы за 12 месяцев. Сроки внутри этого периода распределяются по прежней нормованной сегментной кривой. Это предположение о времени поступлений, которое также требуется проверить на истории компании. Поступления после 12 месяцев не достраиваются. При этом бюджет может продолжаться дольше, поэтому календарь коштів может иметь, например, 18 месяцев. Стресс сдвигает сроки тех же модельных поступлений; он не создаёт новые платежи за пределами годового прогноза.

## 3. Выбрать план и бюджет

В «Витрати стягнення» задайте общий бюджет. Он используется, пока стратегия не применена. Цена покупки и начальные расходы задаются в «Оцінка портфеля», в раскрываемом блоке параметров.

В «Стратегія · 90 днів» используются те же договоры и выбранный прогноз. Базовые сборы за 90 дней берутся из общей месячной кривой с учётом календарных дней. Прежний отдельный множитель 30% здесь не используется. Ставка дисконта и комиссия синхронизированы с общей оценкой.

Проверьте операционные статусы. Кнопка «Операційні статуси» принимает отдельный JSON {"accounts": [...]} для договоров текущего проекта. Поля записи: loan_id, contact_status (allowed/blocked/unknown), rules_verified, active_payment_plan, legal_review_required, updated_at. Отсутствие статуса не считается разрешением контакта. Явный blocked ограничивает контакты по всем договорам того же заёмщика. Подтверждение правовой допустимости остаётся обязанностью компании.

Выбор карточки «Економний», «Збалансований» или «У межах усієї місткості» меняет просматриваемый вариант. Чтобы он повлиял на инвестиционную оценку, нажмите «Застосувати обраний план».

После применения:

1. Расходы выделенной команды и операций плана заменяют соответствующую часть обычного бюджета на период плана. Регулярные статьи заменяются пропорционально дням. Разовые стандартные статьи заменяются, когда дата конца их месяца попадает в период плана.
2. Дополнительные вручную добавленные статьи сохраняются отдельно. Вне периода стратегии сохраняется общий бюджет.
3. Предполагаемый дополнительный сбор добавляется к соответствующему договору один раз. Прирост ограничен остатком доступной суммы при той же вероятности платежа.
4. Комиссия считается один раз от общего сбора. Множитель будущих расходов применяется и к расходам плана.

Эффекты действий остаются ручными предположениями. Они не доказывают причинный прирост сборов. Планировщик формирует черновики, не отправляет сообщения и не подаёт иски. Неосуществимый по бюджету план не применяется. Снять применённый вариант можно отдельной кнопкой; после этого используется общий бюджет.

Недельные суммы при переносе в месячную оценку относятся к месяцу завершения недели. Поэтому недельный PV стратегии и месячный NPV покупки имеют разные даты дисконтирования. Операционный результат стратегии не включает цену покупки; полная инвестиционная оценка включает её.

## 4. Проверить цену и денежный поток

В «Оцінка портфеля» посмотрите граничную цену, NPV, IRR и устойчивую окупаемость. В «Грошовий потік» проверьте все месячные поступления и расходы, включая период после окончания прогнозных сборов. В «Потенціал вимог» проверьте ожидаемые количества плательщиков, неизвестные оценки и вклад договоров.

NPV учитывает время получения денег. Положительная номинальная прибыль не гарантирует достижения требуемой доходности. Повторные поздние расходы могут приводить к неоднозначной IRR: программа показывает прочерк и использует NPV. Это не ошибка загрузки.

Базовый, стрессовый и благоприятный сценарии используют тот же источник прогноза. Для карты сравнения стресс остаётся относительным: 80% текущей вероятности, +25% будущих расходов и задержка +3 месяца. Снижение NPV делится на цену с начальными расходами. Этот показатель не является вероятностью убытка.

## 5. Запустить Монте-Карло

Откройте «Монте-Карло» и запустите симуляцию. Используются текущие индивидуальные вероятности, условные суммы и сроки, а также применённый план и весь бюджет. При ML-источнике это ML-вероятности; при сценарном — сценарные.

После изменения исходных данных, параметров или стратегии прежний результат помечается устаревшим. Повторите расчёт. Сам расчёт не обучает вероятности и не подтверждает точность модели.

Проверьте три графика: NPV, накопленный денежный баланс и число платящих договоров. Вероятность NPV < 0 отличается от вероятности не вернуть вложения. Полосы денежного потока являются поточковыми диапазонами. Интервалы вероятностей учитывают только численную погрешность симуляции.

JSON результата и CSV симуляций сохраняйте кнопками этого раздела. Полный проект сохраняет входы и настройки для повторного запуска, а не все случайные реализации MC. При тех же данных, версии движка, seed и параметрах результат воспроизводится.

На карте «Ризик — дохідність» сохраняйте оценки разных проектов с понятными названиями. Источник и горизонт добавлены к текущей оценке. Для осмысленного сравнения выбирайте сопоставимые горизонты и бюджеты. Карта хранит потоки, а полный проект — первичные данные; это разные виды сохранения.

## 6. Зафиксировать решение и ввести факт

Перейдите в «Прогноз / факт» и нажмите «Зафіксувати поточне рішення». Программа сохраняет первоначальные входы, прогноз и бюджет. Изменения текущей цены или предположений не переписывают этот снимок.

Введите месяц от 1 до конца календаря, фактические валовые сборы и фактические расходы. Повторный ввод того же месяца заменяет его значения. Отсутствующий месяц показывается прочерком. Расходы вводятся без цены покупки и начальных расходов, относящихся к моменту 0.

Можно загрузить CSV с точным заголовком:

```csv
month,gross,cost
1,200000,90000
2,350000,95000
```

CSV заменяет таблицу месячного факта целиком, поэтому включайте в файл всю нужную историю. Повторные номера месяцев отклоняются. Неполные или незакрытые месяцы сначала приведите к согласованному периоду: программа не определяет полноту наблюдения автоматически.

Процент выполнения сравнивает только одинаковые месяцы с фактом. Накопительный график строится до первого пропуска. Отсутствующий месяц не считается нулевым. Сохранённый первоначальный план остаётся неизменным.

Недельный контроль стратегии хранится по plan_id и не подставляется в месячный факт автоматически: периоды отличаются. Чтобы избежать двойного учёта, месячный факт загружайте отдельной согласованной выгрузкой.

## Сохранение и восстановление

Нажмите «Зберегти проєкт». Храните JSON вместе с исходными реестрами и выгрузками результатов. Он содержит данные, включая историю платежей, поэтому обращайтесь с ним как с рабочим конфиденциальным файлом. Автоматической отправки реестра на сервер нет. В браузере нет корпоративной базы данных и управления ролями.

Для продолжения откройте JSON через верхнюю кнопку. Проект пересчитывается общим движком, сохранённый исходный план сверяется с его входами. При несовместимом файле текущая работа сохраняется. MC запускайте повторно с сохранёнными настройками.

## Python CLI единого проекта

```bash
python python/project.py dist/project-demo.json --output outputs/project-result.json
python python/project.py dist/project-demo.json --mc-params mc-params.example.json --output outputs/project-with-mc.json
node tests/test_project.js
```

CLI вызывает тот же JS-движок через установленный Node.js. Отдельной копии формул нового пайплайна на Python нет. Старый valuation.py сохранён как отдельный сценарный инструмент и не обрабатывает JSON единого проекта.

## Границы применения

Это демонстрационный пилот. Модель обучена на синтетической истории, сроки и эффект действий заданы предположениями. До реальных решений нужны разрешённая история компании, калибровка, временная проверка и правовая экспертиза состава требований и допустимых действий. Налоги, кредитное финансирование и специальные военные/региональные факторы отдельно не моделируются.

Руководство и презентация версии 0.8 описывают прежние раздельные модули. Для связей модулей в версии 0.9 используйте этот файл.
