# Модуль оцінки до покупки — v0.3

## Призначення

З відомостей до дати угоди оцінити ймовірність хоча б одного платежу і валову суму надходжень за наступні 12 календарних місяців. Модель не визначає напевно, хто не платитиме. Результат не є оцінкою причинного ефекту конкретної дії стягнення.

Постачена модель навчена **тільки на синтетичній історії**. Її метрики не є доказом якості на українських портфелях. Новий імпорт не перенавчає модель.

## JSON-пакет

Верхні ключі: `meta`, `snapshots`, `payments`, для навчання додатково `observations`.

### snapshots — один зріз на договір

| Поле | Значення |
|---|---|
| loan_id | Унікальний знеособлений ID договору |
| borrower_id | Стабільний знеособлений ID позичальника; використовується для виключення перетинів між вибірками |
| portfolio_id | ID пакета; один пакет має єдину дату зрізу |
| seller_id | ID продавця; новий для навчання продавець позначається для перевірки |
| as_of_date | Дата доступного перед покупкою зрізу, YYYY-MM-DD |
| issued_at | Дата видачі; не пізніше зрізу |
| segment | bank_early / bank_late / mfo_early / mfo_late |
| principal, interest, penalty | Невід’ємні компоненти номіналу |
| excluded_amount | Задане виключення, не більше номіналу |
| dpd | Невід’ємна прострочка у днях |
| quality | ready / review; review не отримує прогнозу |
| history_complete | Лише JSON true підтверджує повноту історії до зрізу |
| history_start_date | Початок покриття: не пізніше max(видача, зріз − 180 днів) |

Відсутні платежі за непідтвердженої повноти історії **не означають нульові платежі**. Такі договори не отримують прогнозу.

### payments

`loan_id`, `payment_date`, `available_at`, `amount`.

`payment_date` — дата події. `available_at` — дата, коли інформація реально стала доступною. До ознак входять лише платежі з обома датами не пізніше зрізу, в останньому 180-денному вікні. Навіть заднім числом датований платіж, отриманий після зрізу, відсікається.

Суми невід’ємні; повернення й виправлення потрібно попередньо звірити. Непов’язані з реєстром платежі і дублікати зрізів відхиляються. Дані інших позичальників та чутливі демографічні характеристики моделі не потрібні.

### observations — лише для навчання

`loan_id`, `observed_until`, `available_at`, `complete`.

`observed_until` описує кінець покритого подіями періоду, `available_at` — коли повна історія стала відома. Для цілі потрібно complete=true та повні наступні 12 місяців. Молодші або неповні випадки виключаються, а не отримують клас «не платив».

Валова сума цілі обчислюється за payments після зрізу і до кінця 12 календарних місяців включно. Події, не відомі в повній історії спостереження, не включаються. Випадки із сумою понад базу оцінки виключаються й потребують узгодження складу боргу; це обмеження поточної моделі частки погашення.

### meta для навчання

`synthetic`: true лише для синтетичних даних; `extract_as_of`: дата витягу; `horizon_months`: 12. `split`: train_end, calibration_start, calibration_end, test_start, test_end.

У навчанні використано тільки цілі, відомі до першої дати калібрування. У калібруванні — тільки цілі, відомі до першої дати тесту. Заємщики, вже присутні в попередніх вибірках, виключаються з пізніших. Тестові цілі не беруть участі в навчанні, калібруванні або масштабуванні ознак.

## Навчання та прогноз

Python: стандартна бібліотека, numpy, scikit-learn. У поточному середовищі перевірено scikit-learn 1.8.0, numpy 2.3.5. Вебінтерфейс не потребує цих бібліотек: використовує експортовані коефіцієнти, а результати звірені тестом Python/JavaScript.

```bash
python3 python/generate_prepurchase_demo.py
python3 python/prepurchase.py train dist/prepurchase-history.json --model dist/prepurchase-model.json --report dist/prepurchase-validation.json
python3 python/prepurchase.py score dist/prepurchase-model.json dist/prepurchase-case.json --output scores.json
```

Модель: StandardScaler на навчанні; LogisticRegression для події платежу; окрема логістична калібрація на наступній часовій вибірці; Ridge на позитивних випадках для частки погашення, обмеженої [0,1]. Це прозора базова модель. Порівняння з іншими класами моделей робиться на тих самих часових розділеннях; перемога на тесті не припускається наперед.

Перевірка: AUC, Brier, калібрувальні групи, помилка загальних зборів, MAE суми на договір, охоплення зборів верхніми 20% рейтингу. Орієнтир — сегментні частки й суми, обчислені лише на навчанні. AUC не є відсотком точних індивідуальних передбачень.

## Відокремлення від оцінки ціни

Прогноз тут — **12-місячний і валовий**. Сценарна інвестиційна оцінка іншого розділу має 36-місячну криву та витрати. Автоматичної підміни одного іншим немає. Для інтеграції потрібні модель строків, оцінка подальших надходжень, відбір допустимих вимог і узгоджений бюджет стягнення.

Реальне впровадження: власник даних підтверджує повноту, походження й дозвіл використання; перенавчання на місцевій історії; перевірка за продавцями, періодами і видами боргу; контроль змін якості даних і калібрування після запуску.
