# Размещение на GitHub и GitHub Pages

Публикация здесь описана как инструкция. Комплект сам по себе не создаёт репозиторий и не меняет доступ к существующему сайту.

## Сохранить исходники на GitHub

1. Создайте новый пустой репозиторий с веткой `main`.
2. Загрузите **содержимое** папки `npl-investment-lab-v0.8`, а не ZIP одним файлом и не внешнюю родительскую папку. В корне должны быть `README.md`, `run_local.py`, `dist/`, `python/` и `.github/`.
3. Если веб-загрузчик пропускает `.github`, добавьте файл `.github/workflows/pages.yml` через **Add file → Create new file**, скопировав текст из комплекта, либо используйте Git.

Через Git, из корня распакованного проекта:

```bash
git init
git add .
git commit -m "Add NPL Investment Lab pilot v0.8"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/YOUR_REPOSITORY.git
git push -u origin main
```

Замените адрес репозитория своим. Пароли и токены в файлы проекта не добавляйте. Если репозиторий уже существует и содержит другие файлы, сначала согласуйте структуру; инструкция выше рассчитана на новый пустой репозиторий.

## Открыть приложение как сайт

1. В репозитории: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Откройте **Actions → Publish demo to GitHub Pages → Run workflow**, ветка `main`.
3. Дождитесь успешного workflow. Адрес будет в результате deployment и настройках Pages.
4. Последующие изменения в `dist/` на ветке `main` автоматически запускают публикацию.

В комплекте уже есть `.github/workflows/pages.yml`. Он публикует **только `dist/`**, не требует npm, сборки, Python или ML-зависимостей на сервере. Все пути приложения относительные; имя репозитория может быть любым. В репозитории с другой основной веткой измените `branches: [main]` в workflow.

GitHub Pages показывает статический интерфейс, выполняющий расчёты JavaScript в браузере. Он не запускает Python, CatBoost или TabPFN на сервере. Для новых ML-расчётов используйте локальный Python и при необходимости обновляйте результаты демонстрации. Изменение данных в браузере не записывает их в репозиторий.

## Доступ и данные

Для GitHub Free Pages доступен для публичных репозиториев; другие возможности зависят от тарифа и настроек организации. Статический комплект не содержит встроенной авторизации или собственного контроля доступа. Публикуйте здесь только демонстрационные данные.

Импорт в интерфейсе обрабатывается в памяти браузера и не отправляется серверу приложением. Но реальные реестры, результаты и модели с обучающим контекстом не следует добавлять в публичный `dist/`, исходный архив или Git. Для локальных рабочих файлов предусмотрены игнорируемые `private-data/` и `outputs/`.

## Проверка и типичные ошибки

- **404 в корне сайта:** проверьте, что в workflow указан `path: dist`, а `dist/index.html` присутствует в репозитории.
- **Workflow не виден:** проверьте путь `.github/workflows/pages.yml` и наличие файла в `main`.
- **Ошибка публикации:** сначала включите Source = GitHub Actions в Pages; затем повторите Run workflow. Политики организации могут ограничивать Actions или Pages.
- **Сайт показывает старую версию:** дождитесь успешного deployment и обновите страницу с очисткой кеша.
- **ML не запускается на Pages:** это ожидаемо для статического хостинга; Python-команды запускаются локально.
