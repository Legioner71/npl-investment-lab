# Порівняння моделей v0.4

Це відтворюваний експеримент на синтетичних даних. Жодні метрики тут не підтверджують точність на реальних українських портфелях або готовність до інвестиційних рішень.

## Що реалізовано

Три двокомпонентні кандидати: Logistic Regression + Ridge, CatBoostClassifier + CatBoostRegressor, TabPFNClassifier + TabPFNRegressor v2. Класифікатор прогнозує хоча б один платіж за 12 календарних місяців; регресор навчається тільки на платниках і прогнозує частку погашення. Частка обмежується [0,1]. Очікувана сума = відкалібрована P × умовна частка × база вимоги.

Для всіх кандидатів однакові 13 ознак та однакові договори. Ознаки розраховуються функцією `feature_row` з модуля v0.3: лише платежі до зрізу, відомі на дату зрізу. Непідтверджена повнота історії та правова перевірка дають відмову від прогнозу, а не нуль. Обмеження дробової моделі v0.3 збережене: результати понад базу вимоги виключаються, а не обрізаються непомітно. Це потрібно переглянути для реальних випадків зі зборами понад поточний баланс.

## Чотири часові групи

| Етап | Зрізи | Роль |
|---|---|---|
| Навчання | I кв. 2021 | Параметри базової моделі та бустингу; контекст TabPFN |
| Калібрування | I кв. 2023 | Окремий сигмоїдальний калібратор для кожного кандидата |
| Валідація / вибір | II кв. 2024 | Вибір за найменшою портфельною WAPE |
| Фінальний тест | III кв. 2025 | Остаточна перевірка після фіксації вибору |

Наслідки кожного етапу мають бути відомі до початку наступного. Позичальники наступних етапів, присутні в попередніх, видаляються. Портфель має одну дату зрізу і не може потрапити у кілька етапів. Неповні 12-місячні спостереження виключаються. `split_samples` перевіряє ці умови. У звіті є кількість, період і SHA256 списку договорів для кожного етапу.

Для четвертої групи не змінено стару демонстрацію: до копії історії v0.3 додано незалежно згенеровані договори 2021 року з окремим seed. Отримано 4 920 записів; після виключень: навчання 1 600, калібрування 1 600, валідація 576, тест 960; 120 неповних результатів виключені, 64 перетини прибрані. Процес генерації спрощений і близький до логістичної/лінійної залежності; це може сприяти простим моделям. Він не імітує повною мірою зміну українського ринку, воєнні шоки та різницю стратегій стягнення.

## Вибір та метрики

Портфельна WAPE = Σ по портфелях |прогноз зборів − факт зборів| / Σ фактичних зборів. Вибір відбувається тільки за валідацією. При рівності — MAE договорів, потім стабільний ключ моделі. Фінальні тестові цілі не передаються до функції вибору. Кандидат, обраний на валідації, може програти на тесті — цей результат зберігається.

Додатково показано Brier (квадратична помилка ймовірностей), AUC (ранжування), MAE суми договору, знакова помилка загальної суми, портфельне завищення, калібрування за децилями, помилки за продавцями. Перевірка за продавцями — лише діагностика на тих самих продавцях, не перевірка перенесення на нового. 12 портфелів фінального тесту та одна валідація не доводять статистичної переваги; довірчі інтервали не заявляються.

Налаштування зафіксовані до запуску: LR C=1, Ridge α=10; CatBoost 250 дерев, depth=4, learning_rate=0.035, L2=8; TabPFN v2 — один учасник ансамблю, CPU, кеш навчального контексту, батч 128. Це порівняння конкретних конфігурацій, а не повний пошук кращого алгоритму. Калібратор — LR C=1000. Дата/час навчання не є ознакою.

## Відтворення

В окремому Python-оточенні:

```bash
python -m venv .venv-benchmark
# Активуйте оточення відповідно до ОС.
pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements-benchmark.txt
python python/generate_benchmark_history.py
python python/model_benchmark.py run dist/benchmark-history.json dist/prepurchase-case.json --report dist/model-comparison.json --bundle dist/model-bundle.json
python -m unittest discover -s tests -p test_model_benchmark.py -v
```

Старий модуль v0.3 зафіксований зі scikit-learn 1.8.0. Залежності benchmark ізольовані: TabPFN SDK 2.2.1 потребує scikit-learn <1.7. Не регенеруйте старі артефакти в новому середовищі, очікуючи їхнього побітового збігу.

Оцінка нового пакета без підбору моделі на його майбутніх результатах:

```bash
python python/model_benchmark.py score dist/model-bundle.json my-case.json --model catboost --output my-scores.json
python python/model_benchmark.py score dist/model-bundle.json my-case.json --model tabpfn --output my-neural-scores.json
```

Без `--model` використовується кандидат, обраний на валідації. Новий пакет валідується та оцінюється за даними до зрізу. Завантаження нового реєстру не робить синтетично навчену модель придатною для реальних рішень: спочатку потрібні навчання та незалежна перевірка на дозволених даних роботодавця.

## Артефакти та виконання

- `model-comparison.json`: метрики усіх кандидатів, аудит вибірок та прогнози поточного синтетичного пакета. Сайт показує цей зафіксований результат.
- `model-bundle.json`: коефіцієнти базової моделі, дерева CatBoost у JSON, навчальний контекст TabPFN, параметри калібраторів, контрольні суми офіційних ваг. Pickle не використовується для цих артефактів.
- `benchmark-history.json`: відтворювана синтетична історія чотирьох етапів.

Ваги TabPFN v2 завантажуються SDK з офіційного публічного джерела при першому використанні; потрібен інтернет та місце для кешу. Ваги не включено до вихідного ZIP чи сайту. Телеметрія TabPFN вимкнена; реєстри не відправляються до ML API. Виконується локальна попередньо навчена мережа; `.fit` задає контекст, а не навчає ваги трансформера з нуля. Під час завантаження з bundle контрольні суми ваг звіряються.

Сторінка не виконує важкий Python/нейромережевий inference. На ній можна перемикати модель, переглядати готові прогнози та експортувати CSV. Імпорт у звичайній вкладці «Прогноз пакета» залишається на базовій моделі v0.3; це явно зазначено. Для нового реєстру з усіма кандидатами використовуйте Python CLI. Під час підготовки реальних артефактів не публікуйте навчальний контекст та реєстри: вони можуть містити закриті дані. Публікація цього демо включає лише синтетичні записи.

## Зв'язок із ціною покупки

Цей benchmark прогнозує валові надходження за 12 місяців. Він не включає помісячний розподіл, решту надходжень після 12 місяців, витрати, податки чи фінансування. Поточна 36-місячна DCF-сценарна модель працює окремо. Помилка прогнозу валових зборів не є готовою метрикою помилки ціни. Перед інтеграцією потрібні узгоджені строки і бюджет, а також порівняння економічних результатів за фіксованим правилом ціноутворення.
